### Versioning

Ascendo follows a **lockstep release numbering policy** with `macOS_updates`:
- **Policy rule**: The release version of Ascendo matches the version of `macOS_updates` with which it shares functional parity (Ascendo 1.5.5 ↔ macOS_updates 1.5.5).
- **Deliberate jump**: This release jumps directly from `1.1.1` to `1.5.5`. There are **no releases 1.2.0 through 1.5.4**; this is an intentional version synchronization to align numbering across companion projects.
- **Compatibility**: There are **no breaking changes** in the public CLI or REST API contracts. All existing sidecars, configurations, and adapter interfaces remain fully backward compatible.

### Known limitations

- **F1b (dashboard Python on Homebrew `python@3.x`)**: The long-lived dashboard process may hold stale lazy imports after a Homebrew keg cleanup. Recommendation: eager imports at `run_phases` start, or defer `python@3.x` formula matching against `sys.executable` keg. Risk is low: the dashboard is not a long-running daemon in normal use and `shopt -s checkhash` + `hash -r` covers shell-side executions.
- **Spec 9 (runner before/after snapshots)**: Automated pre/post run snapshot hooks remain deferred. Users can invoke manual snapshots via system tooling (Time Machine / Timeshift / VSS) or `ascendo snapshot` if configured.
- **Inventory rows 19 & 22**: Inventory candidate probing for specific edge-case vendor distributions (rows 19 and 22 in parity matrix) remains deferred to a subsequent milestone.
