# Ascendo 1.1.0 — 2026-10-19

Keep-a-Changelog notes for `1.1.0` (no git tag cut yet). Port of the
macOS_updates **v1.4.2 → v1.5.4** behaviour into the Ascendo macOS adapter
(plan: `docs/superpowers/plans/2026-09-29-macos-updates-parity.md`; the plan
text said "→ v1.5.2", the v1.5.4 delta extended it).

## [1.1.0] — 2026-10-19 — macOS_updates parity

### Added

- **Restart-safe softwareupdate**: `-R` apply is deferred to the end of the
  run; verify/cleanup of other categories no longer race a restart.
- **Cross-process run lock** (`~/.ascendo/run.lock`, boot-aware) so the CLI,
  dashboard and scheduler cannot run two applies at once.
- **Unattended sudo gate + keep-alive**: scheduler/`ASCENDO_UNATTENDED` runs
  never prompt; a `sudo -n -v` keep-alive runs for interactive full runs.
- **Rosetta awareness**: one lipo-based Intel-only detector; `rosetta_missing`
  action-required item from `check`; opt-in install in the full profile.
- **Honest scheduler**: bootstrap verified, quarantine stripped,
  `launchctl enable`, cleanup on failure.
- **`clt` health component** (Command Line Tools); the macOS health check now
  has **13 components**.
- **Web status vocabulary**: `feed_stale`, `rollout_hold`, `cli_duplicate`,
  `SUDO_UNAVAILABLE`, `settle_pending`, `app_in_foreground`,
  `app_still_running`, `launched_app_quit`, `mau_pin_stale`, `probe_unavailable`.
- **Web verify quits only apps Ascendo launched**, after the settle window
  (`ASCENDO_WEB_STAGE_WAIT`), never a frontmost app.
- **npm CLI duplicates** reported (`cli_duplicate`); removal is opt-in.
  CLI version retention (old versions pruned unless kept).
- REPORT.md **"Updated outside Ascendo"** section.
- Wheel now ships `lib/**/*.py` and `config/**/*` (sdist ships `/config`).

### Changed

- **OpenCode: native-first** (native installer preferred over npm).
- Inventory/web discovery list only real top-level apps; drift-free reconcile.

### Opt-in environment variables

| Name | Default | Effect |
|------|---------|--------|
| `ASCENDO_NO_SUDO` | `0` | `1` refuses every sudo path (reports `SUDO_UNAVAILABLE`) |
| `ASCENDO_UNATTENDED` | `0` | `1` = treat run as unattended (no prompts); scheduler sets it |
| `ASCENDO_REMOVE_CLI_DUPLICATES` | `0` | `1` lets apply remove duplicate CLI installs (else report-only) |
| `ASCENDO_WEB_STAGE_WAIT` | `90` (0-600) | seconds native updaters get after Ascendo launches an app |
| `ASCENDO_WEB_QUIT_WAIT` | `60` (0-300) | seconds to wait for a graceful quit in verify |
| `ASCENDO_WEB_STALE_DAYS` | `45` | days an app may stay unchanged before `feed_stale` escalates to failed |
| `ASCENDO_MAU_SCOPED_INSTALL` | `0` | `1` = per-app Microsoft AutoUpdate install (spec F4 calls it `ASCENDO_MSUPDATE_INSTALL`; the Ascendo name is binding) |
| `ASCENDO_MAU_MUTATE_PREFS` | `0` | `1` lets Ascendo release a stale MAU `DeferralVersions` pin |
| `ASCENDO_MAS_USER_RETRY` | `0` | `1` retries a still-outdated mas app once in the user session |
| `ASCENDO_INSTALL_ROSETTA` | `0` | `1` installs Rosetta (full profile only) |
| `ASCENDO_KEEP_CLI_VERSIONS` / `MAC_UPDATE_KEEP_CLI_VERSIONS` | `0` | `1` disables pruning of old CLI versions |
| `ASCENDO_RUN_LOCK_FILE` | `~/.ascendo/run.lock` | override the run-lock path (ignores the runs dir) |
| `ASCENDO_SUDO_KEEPALIVE_INTERVAL` | `50` | seconds between `sudo -n -v` keep-alive pings |

Test seams (not for users): `ASCENDO_WEB_MDFIND_BIN`, `ASCENDO_WEB_SP_BIN`,
`ASCENDO_WEB_UPDATER_BIN` (+ `_ALLOW_PREFIX`), `ASCENDO_MSUPDATE_BIN`,
`ASCENDO_ALLOW_REAL_BREW`, `ASCENDO_WEB_SEEN_FILE`,
`ASCENDO_WEB_LAUNCH_TRACK_FILE`, `ASCENDO_WEB_NOW_EPOCH`,
`ASCENDO_ROSETTA_DIR`, `ASCENDO_ROSETTA_PRESENT`, `ASCENDO_HOST_ARCH`,
`ASCENDO_CLT_DIR`, `ASCENDO_LSAPPINFO_BIN`, `ASCENDO_WEB_SLEEP_BIN`.

### Requirements

`python3` **>= 3.11 must be first on PATH** for the macOS adapter scripts
(system `/usr/bin/python3` is 3.9 and has no `tomllib`).

### Known limitations

- softwareupdate verify/cleanup run before its deferred (restart-capable)
  apply, so non-restart labels get no same-run verify.
- `sudo -n true` after a TTY-less `sudo -v </dev/null` Touch ID warm is
  unverified on real hardware (manual check recommended).
- Sudo keep-alive ignores failures until its first success (Ruling 45).
- Not ported: runner before/after snapshots (Spec 9) and inventory rows 19
  (chronic warnings) and 22 (coverage).
