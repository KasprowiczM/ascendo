        1 · Install
        
        
        One-liner via curl|bash from your terminal:
        
        
        curl -fsSL https://raw.githubusercontent.com/KasprowiczM/ascendo/main/install.sh | bash
        
        
        Picks language (en / pl), detects OS (macOS / Ubuntu / Fedora / Arch), asks for install profile (CLI / CLI+Web / CLI+Web+Desktop), then installs deps and clones the repo to ~/.local/share/ascendo. Idempotent — re-running pulls updates.
        

        
        2 · First run
        
        
        After install, open the dashboard or use the CLI. The dashboard auto-launches at http://127.0.0.1:8765 on first run; the desktop app spawns the same backend as a sidecar.
        
        
        python3 -m ascendo doctor              # health snapshot
python3 -m ascendo run --phase check    # find updates (read-only)
python3 -m ascendo run --phase apply    # apply updates (mutating)
python3 -m ascendo dashboard            # open the web UI
        

        
        3 · CLI cheat-sheet
        
        
        The 5-phase contract:
        
        
          
          
        • check — read-only inventory + outdated detection (no sudo)
          • 
          
        • plan — show what apply WOULD do (no sudo)
          • 
          
        • apply — mutate the system; mas + softwareupdate prompt for sudo once via the dashboard's askpass cache
          • 
          
        • verify — re-check installed versions after apply
          • 
          
        • cleanup — prune stale logs / cache
          • 
        
        
        
        python3 -m ascendo runs list -n 5                    # last 5 runs
python3 -m ascendo runs json <run-id> --pretty       # full sidecar
python3 -m ascendo schedule install \
    --name nightly --calendar "DAILY 03:30" --profile safe
        

        
        4 · Per-OS managers
        
        
          
          
        • macOS: brew (formulae + casks), mas (Mac App Store), softwareupdate (OS patches), launchd (scheduler), Time Machine snapshots (read-only via tmutil), npm (Node + bun + global CLIs)
          • 
          
        • Linux: apt, snap, flatpak, brew (Homebrew on Linux), npm, pip / pipx, fwupd, NVIDIA drivers
          • 
          
        • Windows: winget, msstore, registry_arp, PSWindowsUpdate, Task Scheduler, VSS snapshots, UAC, Dell DCU plugin
          • 
        
        

        
        5 · Configuration paths
        
        
          
          
        • ~/.config/ascendo/locale.txt — UI language (en / pl)
          • 
          
        • ~/.config/ascendo/ai.json — AI provider credentials (api_key redacted on read)
          • 
          
        • ~/.ascendo/runs/<run-id>/ — sidecars + per-run stream log
          • 
          
        • ~/.ascendo/apps_excluded.json — packages opted out of apply
          • 
          
        • ~/Library/LaunchAgents/dev.ascendo.<name>.plist (macOS) — installed schedules
          • 
        
        

        
        6 · Dashboard tour
        
        
        Tabs in the sidebar:
        
        
          
          
        • Overview — health snapshot, numbered quick actions (1. Build inventory · 2. Quick check · 3. Safe update · 4. Full dry run · 5. Full update)
          • 
          
        • Categories — per-source view with 5-phase buttons
          • 
          
        • Run Center — custom run config + live verbose terminal stream
          • 
          
        • History — past runs with sidecars
          • 
          
        • Logs — pick a run to inspect raw logs
          • 
          
        • Apps — every detected app with filters (search, category, status), in-config toggle
          • 
          
        • Suggestions — rule-based + AI-powered (3-step provider wizard)
          • 
          
        • Hosts — multi-machine config (edit / add / delete)
          • 
          
        • Sync — Proton Drive / rclone overlay for private files
          • 
          
        • Settings — defaults, theme, scheduler, AI, Touch ID (macOS)
          • 
        
        

        
        7 · Scheduler
        
        
        macOS: per-user LaunchAgent. Linux: systemd timer. Windows: Task Scheduler. DSL: DAILY HH:MM, WEEKLY <DAY> HH:MM, MONTHLY HH:MM, HOURLY HH:MM, MINUTE N.
        

        
        8 · Snapshots
        
        
        macOS APFS local snapshots are auto-managed; tmutil localsnapshot as pre-apply ritual. Linux: timeshift / etckeeper. Windows: VSS via Checkpoint-Computer.
        

        
        9 · Dev-sync
        
        
        GitHub remains source-of-truth for tracked code. Proton Drive (or any rclone-supported backend) holds the private overlay (.env.local, AI keys, machine-local config). Use dev-sync-export.sh / dev-sync-import.sh.
        

        
        10 · AI Suggestions
        
        
        3-step wizard: pick provider → enter API key (or local URL for Ollama / LM Studio) → click Connect → pick model. Implemented: Anthropic, OpenAI, OpenRouter, Ollama, Google Gemini, LM Studio. Suggestions library shows rule-based recommendations even without an AI provider configured.
        

        
        11 · Troubleshooting
        
        
          
          
        • No sudo prompt on apply (macOS) — first apply pops the sudo modal automatically; if not, click the footer pill ("sudo cache") to authenticate manually.
          • 
          
        • Cmd+Tab shows old icon — rebuild the .app via bash bin/launch-desktop-macos.sh --build then run bash bin/refresh-macos-icon.sh to flush the cache.
          • 
          
        • Apps list looks stale — click the Refresh button (top-right of Apps view); the cache is session-scoped and the auto-invalidation only fires on run completion.
          • 
          
        • mas apply silently fails — make sure you're signed into the App Store (System Settings → Apple ID), and run mas account from a terminal to confirm.
          • 
          
        • Where are the logs? — ~/.ascendo/runs/<run-id>/_stream.log (verbose) and <phase>__<source>.log (per-phase). The Logs tab in the dashboard reads these.
          • 
        
        
        
        For the full operator manual see MACOS_QUICKSTART.md and USER_GUIDE.md in the repo.

        1. Install
        
        
        Three install paths on Windows 11 — pick whichever fits:
        
        
        # A — packaged installer (recommended for end users, once shipped)
# Download Ascendo-<ver>-x64-setup.exe or Ascendo-<ver>-x64.msi from
# Releases, double-click. Adds Start-menu + Desktop shortcuts and an
# Add/Remove Programs entry.

# B — winget (when manifest is published)
winget install --id Ascendo.Ascendo

# C — developer / source install (today)
git clone https://github.com/KasprowiczM/ascendo.git D:\Dev_Env\Ascendo
cd D:\Dev_Env\Ascendo
.\bin\install-dev.ps1                  # core + adapters/windows + smoke
.\bin\install-shortcut.ps1             # Desktop + Start-menu icons
        
        
        Re-running install-dev.ps1 after a git pull
        is safe — it's idempotent and re-installs the editable Python packages
        so the dashboard always runs the latest code.
        

        
        2. First run
        
        
        Three equivalent ways to launch the app (CLI / Web / Desktop):
        
        
        
          
        CommandWhat it does
        
          
            
        ADouble-click Ascendo on the DesktopSpawns the FastAPI sidecar, opens the SPA in your default browser at http://127.0.0.1:8765.
        
            
        B.\bin\launch-desktop.ps1Native Tauri 2.x window — the app in a real OS window, not a browser tab.
        
            
        Cpython -m ascendo dashboardServer only; open http://127.0.0.1:8765 yourself.
        
                  
        
        
        
        The first-run wizard at http://127.0.0.1:8765 walks you
        through: language → theme → first inventory scan → category preview
        → upgrade candidates → optional dry-run demo → done. The first

        optional Get-WUList).
        

        
        3. CLI cheat-sheet
        
        
        # Health + inventory
python -m ascendo doctor                                  # 5-component health
python -m ascendo run --category winget --phase check     # one cat × one phase
python -m ascendo run --categories winget,msstore --phases check,plan
python -m ascendo run --categories winget --phases apply  # mutating; UAC prompt

# Run history (CLI runs and dashboard runs share the same store)
python -m ascendo runs list -n 10
python -m ascendo runs show <id>
python -m ascendo runs json <id> --pretty                 # ascendo/run/v1 JSON

# Snapshot / scheduler / dashboard
python -m ascendo snapshot create "before risky upgrade"
python -m ascendo snapshot list
python -m ascendo snapshot restore <id>
python -m ascendo schedule install --expression "WEEKLY SUN 03:00" --profile safe
python -m ascendo schedule list
python -m ascendo schedule remove <id>
python -m ascendo dashboard --port 8765 [--background]

# Validation + tag-release
.\bin\validate-windows.ps1                                # 30s end-to-end smoke
.\bin\run-tag-release.ps1 -WhatIf                         # plan only, no apply
.\bin\run-tag-release.ps1                                 # interactive 'apply' gate
        

        
        4. Scripts & managers reference
        
        
        Every package source implements 5 phases (check, plan,
        apply, verify, cleanup) emitting
        a JSON sidecar to logs/runs/<run-id>/<source>/<phase>__<source>.json
        validated against schemas/phase-result.schema.json (schema v1).
        The orchestrator aggregates the per-run summary into run.json
        (schema ascendo/run/v1).
        
        
        
          
        Source / scriptWhat it does
        
          
            
        winget — adapters/windows/scripts/winget/*.ps1winget-feed apps. check runs winget list + classifies by source prefix; apply runs winget upgrade --silent --accept-source-agreements with per-item progress.
        
            
        msstore — adapters/windows/scripts/msstore/*.ps1Microsoft Store apps + MSIX bundles. Surfaces store entries from winget list; apply uses winget upgrade --source msstore. Microsoft Store auto-refresh in the background can claim updates between phases — Ascendo emits STORE-AUTO-REFRESHED as info, not warn.
        
            
        registry_arp — adapters/windows/scripts/arp/*.ps1Add-or-Remove-Programs entries (legacy MSI / EXE installers). check walks HKLM/HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall; apply is best-effort — many ARP entries don't expose a silent uninstall+reinstall path, so the manager surfaces a manual-action advisory instead of attempting a risky upgrade.
        
            
        windows_update — adapters/windows/scripts/windows_update/*.ps1OS patches (KB cumulative updates, defender definitions, security rollups). Backed by the PSWindowsUpdate module (Get-WUList -MicrosoftUpdate for check, Install-WindowsUpdate -AcceptAll -AutoReboot:$false for apply). First call installs the module from PSGallery if missing.
        
            
        npm — adapters/windows/scripts/npm/*.ps1 (Sesja 58)Node.js global CLIs (claude-code, codex, gemini, typescript, eslint, prettier, …). check uses npm list -g + PyPI-equivalent registry queries; apply runs npm install -g name@latest. No sudo — installs to user-owned %APPDATA%\npm. Stderr-tail surfaces EACCES / registry 404 reasons on failure.
        
            
        pip — adapters/windows/scripts/pip/*.ps1 (Sesja 58)Python global CLIs (uv, ruff, mypy, pytest, black, …) in user-site. apply runs pip install --user --upgrade name. Self-skip rule for the pip package itself when it's the system Python's pip (avoids privilege conflicts).
        
            
        web — adapters/windows/scripts/web/*.ps1 (Sesja 59 → 64)Curated third-party apps installed outside winget (Brave, Obsidian, OBS Studio, KeePassXC, Notepad++, AutoHotkey, GitHub CLI, OpenCode, VSCode User-Setup, etc.). 8 apps Tier-A have full silent install: download installer, verify Authenticode against expected publisher, kill running process, run silent flags, read new DisplayVersion from registry. Sesja 64 added fake-success detection — apply now reads DisplayVersion BEFORE the install too and flips the result to failed if the version did NOT change despite exit 0. Sesja 65 deduped web-auto rows against winget by DisplayName so the same app no longer shows under both categories.
        
            
        plugin — plugins/dell-driver-update/ (Sesja 58 wiring)Dell Command Update plugin — driver + BIOS updates on Dell hardware. Needs Administrator. Health probe reports the dcu-cli.exe path; non-Dell hosts auto-skip with dcu unavailable.
        
            
        snapshot — adapters/windows/scripts/snapshot/snapshot.ps1Pre-apply snapshot via Volume Shadow Copy (vssadmin create shadow). Bounded by a 300s timeout — never stalls the run; falls through to a warn diagnostic if VSS is disabled or the system drive is read-only.
        
            
        scheduler — registered through schtasks /CreatePer-user Task Scheduler entry \\Ascendo\\WeeklyRun. Trigger string is cron-like or schtasks-native; the scheduled job runs python -m ascendo run with the saved profile and battery / focus / window guards (ASCENDO_REQUIRE_AC=1, ASCENDO_MAINTENANCE_WINDOW=02:00-05:00).
        
            
        elevation — adapters/windows/ascendo_windows/managers/elevation.pyUAC-based elevation. Allowlists native binaries by basename (lowercase), denies on non-Windows, runs the helper with ShellExecute + runas. The dashboard caches the Administrator token in-memory only — never on disk.
        
            
        plugins/dell-driver-updateFirst-class plugin: 5 PowerShell phase scripts (StrictMode-safe), enumerates Dell driver / firmware updates via Dell Command | Update CLI, sidecars saved as <phase>__plugin.json.
        
            
        bin/launch-desktop.ps1Wraps npm run tauri dev (default) or npm run tauri build (-Build). Prereq check for Rust + MSVC + Node before launch; offers exact winget commands when something is missing.
        
            
        bin/validate-windows.ps130-second end-to-end smoke: starts the dashboard on a free port, hits /categories, /inventory/summary, /runs/active, posts an async check run, asserts SSE events arrive, kills the dashboard cleanly. CI-grade.
        
            
        bin/run-tag-release.ps17-phase tag-release helper from elevated PowerShell: preflight → snapshot → plan → confirm-gate → apply → verify → cleanup → doctor. -WhatIf stops at plan.
        
            
        dev-sync/dev_sync_export.pyPush private overlay (.env.local, agent settings, keys) via rclone to your cloud provider. Copy semantics, never sync-with-deletes.

        6. Dashboard tour
        
        
        Sidebar items, top-down: Overview (status donut + per-source bar
        + reboot banner + quick actions), Categories (4 sources with
        per-source 5-phase buttons; expand a row for the package list with
        installed / candidate / status pills), Run Center (kick off a run

        AI advice as diffs — nothing applies without your click), Hosts
        (multi-host preflight via SSH), Settings (defaults, theme,
        scheduler, AI provider, backup), Help (this page), About
        (version, host info, release notes).
        

        
        7. Scheduler & maintenance windows
        
        
        Settings → Scheduler installs a per-user Windows Task Scheduler
        entry (\\Ascendo\\WeeklyRun). The scheduled job calls
        python -m ascendo run with the configured profile,
        gated by environment guards so it skips when the laptop is on
        battery / outside the maintenance window / Focus Assist is on:
        
        
        setx ASCENDO_REQUIRE_AC 1
setx ASCENDO_MAINTENANCE_WINDOW 02:00-05:00
setx ASCENDO_RESPECT_FOCUS 1
        
        
        Use schtasks /Query /TN \Ascendo\WeeklyRun /V to inspect
        the trigger; python -m ascendo schedule list shows the
        same info from Ascendo's view.
        

        
        8. Snapshots & rollback (VSS)
        
        
        With --snapshot (or the toggle in Settings), Ascendo
        creates a Volume Shadow Copy snapshot before any apply phase via
        vssadmin create shadow /for=C:. Snapshot creation is
        bounded by a 300s timeout — the run never stalls if VSS is slow
        or the writer is busy. To roll back:
        
        
        python -m ascendo snapshot list                  # shows GUID + timestamp
python -m ascendo snapshot restore <id>          # interactive confirm
        
        
        The dashboard's POST /snapshots/restore takes
        {"id":"<snap-id>","confirm":"RESTORE"}. Note that VSS
        is best-effort — it doesn't roll back user data outside the
        protected-volume snapshot, just system state and program files.
        

        
        9. Dev-sync (cloud overlay)
        
        
        Workflow separate from updates. GitHub holds tracked files. A cloud
        provider (Proton, Google Drive, Dropbox, OneDrive, WebDAV/Nextcloud,
        S3, local) holds a small private overlay (~8 files: tokens, agent
        settings). The Sync screen lets you pick the provider; first-time
        auth happens in a real PowerShell window because rclone needs an
        OAuth callback (no headless first-time flow). Then dry-run + real
        export from the dashboard.
        

        
        10. AI Suggestions
        
        
        Heuristic engine runs free, deterministic rules over inventory + run
        history. Optional LLM step enriches rationales — never edits
        files autonomously. Supports Anthropic (Claude), OpenAI, Google
        Gemini, Ollama (local), LM Studio (local), or any OpenAI-compatible
        endpoint. Local providers need no API key; just set the Base URL
        (Ollama: http://127.0.0.1:11434, LM Studio:
        http://127.0.0.1:1234/v1). All apply paths show a unified
        diff with manual confirm.
        

        
        11. Troubleshooting
        
        
          
          
        • "Apps menu is empty / Categories shows one mash-row" —
          you're running an old SPA in your browser cache. Close the browser
          tab, kill any lingering python.exe, re-launch via
          the Desktop shortcut or .\bin\launch-desktop.ps1, then
          hard-reload the page (Ctrl-Shift-R).
          • 
          
        • "a run is already in progress" 409 —
          POST /runs/active/stop from the dashboard, or remove
          the stale lock at
          %LocalAppData%\Ascendo\ascendo.lock after verifying
          no python.exe holds a handle to it (handle.exe ascendo.lock).
          • 
          
        • winget says "package is currently installing" — Microsoft
          Store auto-refresh is holding the package lock. Wait ~30s, or open
          Store → Library → "Get updates" once and let it finish.
          • 
          
        • UAC prompt declined → run shows red apply — the helper
          process needs Administrator. Click "Authenticate" in the SPA when
          prompted, or run python -m ascendo dashboard from an
          elevated PowerShell so the elevation token is inherited.
          • 
          
        • PSWindowsUpdate import error on first windows_update check —
          the module installs from PSGallery on first call;
          Set-PSRepository -Name PSGallery -InstallationPolicy Trusted
          if you've never used the gallery before.
          • 
          
        • Tauri build fails with MSVC error — re-read
          .\bin\launch-desktop.ps1's prereq output; you likely
          need the C++ workload added via vs_installer modify --add Microsoft.VisualStudio.Workload.VCTools
          (the bootstrapper alone isn't enough).
          • 
          
        • Dashboard tab loads blank — Ctrl-Shift-R, then check the
          browser console (F12). Common cause: stale browser cache after a
          git pull; the cache buster only triggers on script
          name changes.
          • 
          
        • An app shows outdated despite being manually
          upgraded (Sesja 66) — stale post-apply
          overlay from an older triggered run was leaking through
          newer up_to_date checks. git pull + restart
          dashboard; _latest_check_overlay now only walks
          same-run apply/verify.
          • 
          
        • winget list Version=Unknown package re-applied
          every full run (Sesja 66) — plan +
          apply now consult the Sesja 63 apply-mark; a successful upgrade
          short-circuits to up_to_date on subsequent runs.
          • 
          
        • Inventory shows fewer rows than winget list /
          MSStore (Sesja 67) — pre-v2 the DB
          PK was (category, name) which silently dropped 17
          MSStore + 14 winget + 3 ARP packages sharing DisplayNames across
          architectures. git pull auto-migrates; next live-scan
          repopulates within seconds.
